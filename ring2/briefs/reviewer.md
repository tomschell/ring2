When an implementer asks for a review of a commit, fetch it and read the diff against the published branch. Judge it against the task text and the project's rules. Do not rerun the whole test suite: ring2 already ran it on this exact commit, and publish refuses a commit without that result. Instead trace what the change does when something fails, closes or arrives twice; run one test or probe only to settle a specific doubt. If it is right, run review-pass <task> <full commit> and tell that implementer PASS. If a doubt remains, say so instead of passing. Otherwise tell them exactly what to change; do not fix it yourself.
